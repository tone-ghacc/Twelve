# 固定鍵盤区間

schemaVersion 1 に省略可能な `fixedKeyboardSections` を追加。省略時は従来どおり。

```json
{
  "fixedKeyboardSections": [
    { "id": "keyboard-1", "startMs": 10000, "endMs": 18000, "widths": [3, 2, 2, 2, 3] }
  ]
}
```

- 時間範囲は開始を含み終了を含まない。譜面内の整数ms、開始 < 終了。区間同士の重複は不可、隣接は可。
- `widths` は1〜6個の正整数、合計12。配列から境界を累積計算する。分割数は表示のプリセットであり、判定に分割数別の分岐はない。
- **分割は見た目のみ。入力は従来の12レーン・隣接1レーン許容を維持する。**
- 区間内のタップ・フリック・ホールド本体・終点フリックは、1つの鍵盤の左端と幅に完全一致させる。複数鍵盤を覆うノーツや、鍵盤より細いノーツは禁止。区間と重なるホールド本体にも適用する。
- 区間内で連結する場合、前のホールド本体・終点・次のホールド本体は同じ鍵盤に置く。異なる鍵盤をまたぐ連結は禁止。区間外の従来の連結仕様は維持する。
- 制作画面の「固定鍵盤区間」で追加・変更・削除でき、タイムラインにも境界を表示する。JSONの読み込み・保存・ダウンロードは既存処理を利用。
- 区間内でノーツを配置すると、指定した鍵盤の左端と幅に自動で合わせる。既存ノーツの編集・区間の変更・JSON読み込み時も検証し、違反があれば理由を表示して変更を取り消す。
- 旧仕様で保存済みの違反譜面は削除せず、制作画面に読み込んで修正できるようにする。修正完了までは再生できない。

## ランダム

プレイ設定で開始前に有効化する。表示予定のノーツが途中で飛ばないよう、プレイ準備時に各区間の `originalGroup -> randomizedGroup` 置換を一度確定し、そのプレイ中は維持する。`groupPermutation` は鍵盤数と同じ長さの配列。やり直しでは再生成。一時停止では維持。分割配列自体は変更しない。

ノーツJSONを複製して、左端レーンと幅を移動先の鍵盤に合わせてから既存の判定イベントを生成する。例えば `[3,2,2,2,3]` の鍵盤0（左端0・幅3）を鍵盤1へ移すと、ノーツは左端3・幅2になる。逆に2幅から3幅への拡張にも対応する。ホールド本体・終点フリック・連結先も同じ置換を使い、途中で幅やレーンが変化する形状は作らない。描画と判定が同じ変換済みデータを見る。編集元JSONには置換を保存しない。区間外のノーツは元のレーン・幅に置く。

1〜6鍵盤の全単射をFisher–Yatesで生成する。区間境界をまたぐホールド・連結チェーンは、そのチェーン全体と使用鍵盤の対応を固定し、残りの鍵盤だけを入れ替える。終点が区間終了と同時刻の場合も固定する。全鍵盤が固定される場合や1分割では恒等置換になる。

## 表示と寿命

`Game.fixedKeyboard` の `active` は現在の区間、`effects` は開始済みの光演出を保持する。開始時に1回だけ光を登録し、終了時は `active` を解除するが、`effects` は独立に0.65秒の寿命を終えるまで残す。続けて別区間が始まった場合は複数の光を同時に扱う。一時停止では演出も停止し、譜面終了直前の光はリザルト中も完走する。

遠近計算の `progress` / `laneX` / `laneScale` を流用し、画面手前の外側から最奥の外側へ光を走らせる。通過済みの部分だけを塗り分け、分割線を形成する。区間終了後は分割線と塗り分けを即座に消し、光だけを残す。ノーツ速度・判定時刻には影響しない。
