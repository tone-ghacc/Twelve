# ノーツ移動と遠近表示

判定時刻を `tNote`、音声時計から得る譜面時刻を `t`、全行程の所要時間を `T` とし、`q = 1 - (tNote - t) / T` を使う。`q=0` が最奥、`q=1` が判定線。表示時間テーブル・速度設定・判定窓は変更しない。

## 修正前

画面内の進行率は `p = 0.28q + 0.72q^2.2`。画面位置は `y = topY + (hitY-topY)p`、見かけの幅の倍率は `s = 1/6 + 5p/6`。

ピクセル単位の速度は増加するが、見かけのレーン幅あたりの速度 `(dy/dt)/s` は後半で低下する。高さ700px・速度10の例では、q=0.5で約1772、q=1で約1411となり約20%低下。画面上の位置そのものの減速ではなく、拡大率に対して移動量が相対的に小さくなる挙動が、減速感の一因と考えられる。

また、未判定のホールド始点・フリックホールド終点を判定線にクランプしていたため、判定時刻を過ぎると実際に停止していた。

## 修正後

最奥と判定線の幅の比 `r=0.10/0.78`、`a=ln(1/r)` として、`p = r × (exp(aq)-1)/(1-r)`。

判定線を1とする相対倍率は `s = r exp(aq)`、`dp/dq = a s/(1-r)`。実際の描画倍率は最手前を1として `S = 0.78s` を使う。そのため、`(dy/dt)/S = (hitY-topY)/T × a/[0.78(1-r)]` は一定。奥行きに応じて画面上の移動と拡大が釣り合い、最奥から判定線へ近づく途中で相対的な速度が落ちない。これは見かけの速度感を揃えるための時間パラメータ化であり、3D空間内の等速運動を仮定した式ではない。

## ステージの幅と判定位置

`dist/projection.mjs` の `STAGE_PERSPECTIVE` に、最奥 `farWidth=0.10`、判定線 `judgementWidth=0.78`、最手前 `nearWidth=1.00` をまとめて管理する。定数を変更する場合は `0 < farWidth < judgementWidth < nearWidth` を維持する。

画面高さを `H`、横幅を `W` として、横幅倍率は `S(y)=farWidth+(nearWidth-farWidth)y/H`。レーン境界は `x(lane,y)=W/2+(lane/12-1/2)WS(y)`。これは既存の直線状の透視レーンの断面の幅であり、ノーツの時間移動を線形に置き換えるものではない。

側面を直線のまま3つの指定倍率を満たすため、判定線の高さは `hitY/H=(judgementWidth-farWidth)/(nearWidth-farWidth)=0.755555…` とする。710×372pxの再生領域では最奥71px、判定線553.8px（Y=281.07px）、最手前710px。参考画像の絶対幅ではなく、指定の正規化した比率を優先する。

レーン、ノーツとホールド本体、固定鍵盤の境界と演出、判定枠、ビーム、ヒットエフェクトは共通の投影を使う。ノーツの厚みとフリックのインジケーターも同じ倍率に従う（細い線には視認性のため最小ピクセル幅を残す）。入力X座標は判定線上の投影済みレーン境界から元の12レーンへ変換する。押下の端へのクランプと範囲外フリックの無効化は維持する。

表示時間テーブル、速度設定、音声時計、判定窓、レーン番号や譜面データの配置は変更しない。遠近比率を反映するため画面上の位置・拡大率の曲線は調整されるが、出現時刻と判定線への到達時刻は維持される。制作タイムラインには適用しない。

判定線を越えても同じ曲線を使う。画面外へ出た後だけ接線による直線外挿に切り替え、長時間ホールドで指数が過大にならないようにする。

未判定の始点・終点フリックの表示も直接この位置を使う。ホールド本体の、判定線より手前の消化済み部分を切り取る処理は分離して維持する。判定時刻や猶予、連結の扱いは変更しない。

`requestAnimationFrame` は描画の呼び出しに使用し、位置は毎回 `AudioContext.currentTime - epoch - chartDelay()` から算出する。deltaTimeによる積分や前フレームへの補間はない。フレーム落ちで表示が飛ぶことはあり得るが、移動速度や到達時刻はフレーム数に依存しない。
